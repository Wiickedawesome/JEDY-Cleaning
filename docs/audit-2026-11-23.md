## Contact-form incident (root causes)

1. **False success.** FormSubmit returns `success` as a string, so `if (data.success)` treated
   `"false"` as success. Fixed by requiring a 2xx status and `success === true`.
2. **Per-origin activation.** FormSubmit activates per origin, so localhost submissions were
   rejected while the live domain worked — local previews could never validate delivery.
3. **Stalled requests.** The POST could be accepted with no response, leaving the button at
   "Sending..." indefinitely. Fixed with an abort after 12 seconds.
4. **Browser-level rejection.** Confirmed by the owner that real browsers received
   "Something went wrong" on FormSubmit. The provider was replaced rather than worked around.

**Provider decision:** Web3Forms (free: 250 submissions/month, unlimited forms and domains,
built-in spam filtering, no origin activation, client-side key). Formspree's free tier is 50
submissions "for testing and development". Resend needs a server-side key, which a GitHub Pages
static export cannot hold without adding a Worker plus SPF/DKIM/DMARC records. Self-hosting mail
was rejected on deliverability grounds.

⚠️ Web3Forms rejects server-side requests on the free tier (HTTP 403), so the access key can only
be validated from a browser.
